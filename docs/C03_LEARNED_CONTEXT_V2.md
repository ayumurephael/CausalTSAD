# C03v2：学习因果条件机制上下文

C03固定交叉矩未改善预测，不能据此否定可学习上下文。C09的学习条件尾分布在独立源验证中优于边际分位数，错误条件会损害校准，但整体目标TSAD未稳定改善。这里检验一个更具体的问题：过去的条件输入/创新配对能否在前向中识别本系统的正常机制，而非只用一套跨系统平均校准。

完整读过CNP(ICML2018)10页及固定作者全部核心代码。采用其共享配对编码/对称汇总/查询条件解码；这些不是新发明。不把deterministic summary称贝叶斯后验，不声称已经恢复SCM系数或完成C03整张卡。

输入复用原C09的12个合法预测特征与已经发生的创新。对每个通道，共享13→32→32编码器编码过去配对；当前t的上下文为三个64点块，各块最后端不晚于t−16（右开区间）。均值或三块坐标中位数得到32维上下文，连接当前12个合法条件特征，44→64→64→9分位数预测器输出当前正常创新分布。当前/未来创新不进入自己的预测分布；同刻父值只通过原冻结C02合法特征进入。原TimeRCD离线支路保持，不能声称全模型在线或future-blind。

3臂no_context/learned_mean/learned_median × 3优化种子348–350。no_context同样计算编码器/全部槽位但摘要置零，因此名义容量/Linear FLOPs相同、有效容量不同。3块中位数只是有限污染启发式，无严格鲁棒性保证。各臂同初始化、同数据、同顺序与查询mask。每个seed的3臂放同GPU型号，seed348/349在H100，seed350在A100；不是3独立预训练模型。

固定3遍正常密度＋3遍冻结密度的融合训练，各936updates。统一前256点只保留原TimeRCD且不计新分支loss，C1完全保留common multi。每run每阶段完整M输入11,931,648、有效查询8,948,736；9run正常密度80,538,624、观测融合80,538,624、额外正常融合80,538,624。密度训练不反传异常观测。源验证初始/第1遍/密度终点/融合终点预先固定，额外前向单列；查询上下文会重用过去embedding，不能把这些操作算成0。缓存复用0新teacher/encoder；哈希与旧C09一致。

源验证保留当前查询条件不变，仅换成另一个同C系统的历史摘要；另测observed历史条件化normal查询的污染诊断，该normal仅源审计，不进目标模型。记录pinball/覆盖率/错上下文代价、源观测AP和ready注入窗RCA。完成后固定final评估同100 development全部4指标/AP/FPR；完整标签点集不裁掉前256。目标validation/locked不打开、所有目标0反传、不按目标选checkpoint或阈值。
